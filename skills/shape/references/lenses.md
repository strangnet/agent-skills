# Lenses

Pick the two or three lenses that fit the idea. Running all of them produces many shallow variations, and the goal is a few genuinely different ones.

## Generating variations

- **Simplify.** What is the version that is ten times simpler? What could be deleted entirely?
- **Invert.** What if the opposite party did the work, or the steps ran in reverse?
- **Remove a constraint.** What if time, budget or the current technology weren't a factor? Then put the constraint back and keep what survives.
- **Add a constraint.** What if it had to ship in a day, have one feature, or avoid the obvious technology?
- **Shift the audience.** What if it were for a different user, or for the same user in a different situation?
- **Borrow structure.** Which other domain has already solved a structurally similar problem? Look for the same shape of problem, not the same surface.
- **Reuse what exists.** What in the codebase already does most of this? What is the smallest extension of it?

## Finding the real problem

- **Jobs to be done.** "When I <situation>, I want to <motivation>, so I can <outcome>." The competitor is whatever the user does today instead.
- **First principles.** List what is known to be true and what is only assumed. Rebuild from the truths alone.

## Stress-testing a direction

- **Value.** Does it solve an acute, frequent problem (a painkiller) or make something marginally nicer (a vitamin)? Can you name someone who has this problem now?
- **Feasibility.** What is the hardest part? Is it a known-hard problem or a new one? Which dependencies are outside your control?
- **Pre-mortem.** It's a year later and it failed. List the plausible reasons. Which are preventable, and which mean the idea should change?
